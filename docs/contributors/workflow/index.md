Use these guides in order:

1. [Git workflow](../../git-workflow.md) — create and update branches and commits.
2. [Life cycle of a pull request](../../pull-request.md) — prepare, submit, and finish a pull request.
3. [Code reviews](../../code-reviews.md) — understand reviewer and author responsibilities.

Before requesting review, make the change understandable without a private explanation. Include the problem, approach, test evidence, screenshots when behavior is visual, and rollout risk when behavior affects production.
